# L8: buildroot on RD68031

Buildroot's own glibc toolchain and userspace for RD68031 and its RD68884 FPU, with
the same kernel as L7: Linux 7.2.9 with `patches/linux`, the m68k LiteX machine. The
SoC, litexboot and the way the images reach main RAM are L7's (`doc/l7-linux.md`).

```sh
buildroot/build.sh                    # -> ~/LITEX-68K/build/buildroot-fpu/images
sim/litex/l7_test.py --login --linux-dir ~/LITEX-68K/build/buildroot-fpu/images \
    --build-dir sim/litex/build/standard+fpu/l8          # in litex_sim
sim/litex/l7_test.py --login --linux-dir ~/LITEX-68K/build/buildroot-fpu/images \
    --serial /dev/ttyUSB0 --speed 1000000 \
    --build-dir build/qmtech_wukong_30m_fpu_1m_fix       # on the Wukong, BIOS at its prompt
```

## The pieces

- **`buildroot/`**, a br2-external tree (`external.desc`: `LITEX68K`). It has no
  packages of its own yet, only a board and a defconfig.
  - **`configs/litex_rd68031_fpu_defconfig`**:
    - `BR2_m68k_68030`, which does not select `BR2_SOFT_FLOAT`, so hard float:
      gcc's `-mcpu=68030` with the 68881's instructions.
    - Buildroot's toolchain: gcc 15.3, glibc 2.44, the kernel's own headers.
    - The kernel from the 7.2.9 tarball with `patches/linux`, and
      `board/litex-rd68031/linux.defconfig`. Its image is `vmlinux`, which
      litexboot loads.
    - BusyBox with `busybox.config` over buildroot's configuration: awk's
      math functions, which buildroot leaves out ("Math support is not
      compiled in") and L7's command set uses.
    - BusyBox init, a getty on `ttyLXU0` (LiteUART) at the line's speed, root
      without a password, devtmpfs. No network scripts.
    - Lua, beyond BusyBox: double-precision arithmetic through glibc's libm.
    - A gzipped cpio root filesystem, which litexboot hands the kernel as its
      initramfs.
    - Every download is checked by hash
      (`BR2_DOWNLOAD_FORCE_CHECK_HASHES`). The kernel's hash is in
      `board/litex-rd68031/patches/{linux,linux-headers}/`, the one
      `linux/MANIFEST` has.
  - **`board/litex-rd68031/linux.defconfig`** is generated by
    `make-linux-defconfig.sh`: allnoconfig with L7's `linux/litex-rd68031.config`
    and `linux-buildroot.config`, saved by `savedefconfig`. Buildroot expands it
    with `olddefconfig`, which gives back the same configuration. L7's
    configuration thus stays the one source.
  - `linux-buildroot.config` adds what buildroot's userspace needs over L7's:
    UNIX sockets (syslogd) and ptys (devpts, in its fstab).
  - `post-image.sh` names the initramfs as `linux/build.sh` does, so that
    the images directory is a `--linux-dir` for `l7_test.py`. `images.json`
    depends on the SoC, where its main RAM is, so `l7_test.py` writes it.
- **`buildroot/build.sh`**:
  - Buildroot 2026.08 comes from `linux/fetch.sh` (`linux/MANIFEST`: the
    sha256 the release's signed hash file gives). It is unpacked, never
    changed, into `~/LITEX-68K/src/buildroot-2026.08`.
  - The output is `~/LITEX-68K/build/buildroot-fpu`, the downloads
    `~/LITEX-68K/dl/buildroot`. `BR2_JLEVEL` is 4 (CLAUDE.md).
  - Extra arguments are make targets: `buildroot/build.sh "" linux-rebuild`
    rebuilds the kernel after a change in `patches/linux`'s tree.
- **`l7_test.py --login`** waits for the getty's `login:`, logs in as root, and
  runs L7's command set and `LOGIN_COMMANDS`:
  - `/etc/os-release` is buildroot's, and `/lib/libc.so.6` is there: the
    programs are dynamically linked against glibc.
  - Two Lua computations in doubles (`sin`, `exp`, `log`, `atan`, `sqrt`, and
    a sum of 2,000 `sin·cos` products), checked against the host's values.
    glibc's m68k libm computes them with the 68881's own instructions
    (`fsin`, `fetox`, ...), so they are RD68884's.

## Results

| | litex_sim (32 MiB, CPU and sys at 1 MHz) | Wukong (256 MiB, CPU 30 MHz, sys 100 MHz) |
|---|---|---|
| Build (`buildroot/build.sh`, from nothing, `-j4`, on the host) | 30 min | 30 min |
| Images | vmlinux 3.9 MB (3.2 MB stripped, against L7's 2.6 MB: the networking core), rootfs.cpio.gz 1.9 MB (4.0 MB unpacked) | |
| Upload (`litex_term --images`, 1 Mbaud) | none: `--ram-init` | 210 s |
| litexboot to `login:` | 2615 to 2725 s (L7, to its shell: 793 to 911 s) | 54 s (L7: 19 s) |
| Command set, L7's and `LOGIN_COMMANDS` | pass | pass, twice, each from a fresh load |
| Two Lua processes preempting each other, sums of 30,000 `sin·cos` ×3 | | pass, every sum exact (0.732234782) |

- **Boot time.** Buildroot takes about three times as long as L7's
  static BusyBox to get to the shell, presumably because every program now loads glibc
  dynamically, and the init scripts start syslogd, klogd and crond and run sysctl
  and seedrng before the getty.
- **The command set in the simulation.** The two awk preempting each other
  take 942 s, against 847 s on L7's static BusyBox. The first run hit
  `l7_test.py`'s per-command limit, then 900 s. That limit is now
  `--command-timeout`, 1800 s by default, and each command's time is printed.
- **A build from nothing** gives the same root filesystem file list, the same
  libc, libm and Lua, and the same kernel and BusyBox configurations as an
  incremental one. The binaries are not byte for byte the same, because
  BusyBox and the kernel record their build time.
